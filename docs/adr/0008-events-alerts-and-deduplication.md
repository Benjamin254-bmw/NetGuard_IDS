# ADR 0008: Events, alerts and deduplication
Status: accepted. `security_events` is the incident record and carries the investigation status
(new, investigating, resolved, false_positive). `alerts` are notifications about events with their
own lighter workflow (new, acknowledged, dismissed); keeping the two statuses separate avoids two
sources of truth for one concept. Alert history is the alerts table plus `audit_logs`.
Deduplication: one *open* event per `dedup_key` (rule + source), enforced by a partial unique
index. Repeat detections update `hit_count`/`last_seen_at` instead of inserting; once the cooldown
passes the monitor closes the window (`is_open = false`) and the next detection opens a new
event. Because the database enforces it, two monitor instances cannot create duplicates.
`event_uuid` (generated by the monitor) makes spill-file replay idempotent via ON CONFLICT DO
NOTHING. `detected_at` is the monitor's detection time and `created_at` the DB insert time; the
evaluation harness reports latency against `detected_at` and notes the difference.
